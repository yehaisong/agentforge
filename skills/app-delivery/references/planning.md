# Planning mode

Convert the user's goal into observable behavior and a bounded implementation scope. Inspect the existing workflow before proposing replacements. For ambiguous requests, use available evidence to advance independent work and ask only about choices that materially change the result.

Capture the triggering user action, resulting behavior, domain invariants, relevant failure cases, and acceptance evidence. Break large changes into independently reviewable slices with dependencies; do not invent issue numbers or delivery dates.

Record an architecture decision when it affects future work: decision, alternatives that matter, reason, and consequences. Reuse existing ADR or plan locations. Preserve the distinction between proposed and implemented behavior.

Output a scoped plan or issue draft sufficient for implementation. Use the issue template when useful. Planning alone does not authorize implementation or external issue creation.
